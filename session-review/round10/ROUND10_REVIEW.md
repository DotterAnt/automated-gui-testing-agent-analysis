# Snipping Tool session review — round 10

The main obstacle was a process-ownership assumption that does not fit Explorer, single-instance applications, or system-hosted dialogs. The framework rejected a legitimate GUI route and lacked a supported way to track the window opened by a subsequent cross-app GUI action. The agent then spent substantial effort on launch wrappers. Those wrappers were both outside the intended GUI route and unreliable cleanup targets.

The supplied rollout spans **28 minutes 46 seconds**, with **102 tool calls**, **115 directly returned CLI command envelopes**, and **eight failing script executions**. No execution passed all five rows. The final script was delivered after another static validation, without replaying its last changes. Direct CLI durations total 195.325 seconds; the eight recorded replays total another 149.271 seconds. These are different timing populations, not a controlled before/after benchmark. The reported hardware problems further limit performance conclusions.

The attachments were parsed as evidence and left unchanged. Their scripts, embedded commands and instructions were not executed. Source hashes, compact timeline, messages, metrics and replay summaries are saved alongside this report.

## Window ownership and cleanup

Shared-host receipts carry a native handle, PID, process start time, class and a window-lifetime token. The token is metadata on that native window; Windows discards it when the window is destroyed. This prevents an old receipt from closing a later window that reuses its numeric handle. Cleanup never kills the shared host or closes its other windows. Visible unresolved save prompts remain failures and preserve recovery context.

Interaction scope is independent of cleanup ownership. Focusing a borrowed or shared window does not authorize typing into every sibling window in that process. Guarded broker typing checks the exact foreground root and native focus before dispatch and during text delivery. Clipboard and application-shortcut constraints remain unchanged.

No Snipping Tool, Photos, Explorer, printer or application-specific selectors/content were added to the implementation. The fixes apply to shared GUI hosts, cross-app openings, native edit fields and external dialogs generally.

## Verification and practical limits

**341 regression checks and both live GUI suites passed on Windows PowerShell 5.1.** The runner and per-suite results are in `verification.json`. The GUI suites exercise ordinary input/drag/dialog behavior and the new shared-host lifecycle. They check immediate-exit handoff, claiming a GUI-opened window, rejection of preexisting/stale windows, exact path readback and replacement, sibling-window input rejection, preserving the shared host during cleanup, and refusing/allowing exploration completion before/after the owned window closes. The broker fixture checks typing and navigation without changing the main app context.

The final full Snipping Tool testcase has **not** been rerun here. This review does not claim it now passes or predict a session duration. The supplied script still contains launcher wrappers, broad pre-close actions, relative filenames and an unconditional recovery drag; it should be regenerated from a fresh GUI walkthrough with both updated repositories. Image-only PDF content and uncropped image verification remain testcase responsibilities; a PDF prefix or window title is insufficient. Single blocking UIA provider calls can still exceed a retry deadline.

Use the round-10 CLI and framework packages together. CLI help, AGENTS.md, AUTHORING.md, the generated-script contract and the API authoring prompt describe the supported file-manager and dialog routes. Changes are in the working trees; no commit or PR was created.
